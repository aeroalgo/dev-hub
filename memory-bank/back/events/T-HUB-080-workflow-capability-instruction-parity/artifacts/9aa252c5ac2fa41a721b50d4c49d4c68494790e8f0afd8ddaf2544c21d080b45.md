# Bugfix: Session close identity desync

## Root cause
После `mb-finish bugfix` live `armed_step` становился QA, а:
1. ownership gate сравнивал fence verify-bugfix (`step_id=BUGFIX`) с live cursor QA → `semantic_ownership_mismatch` / `verdict_wrong_step`;
2. `finish_bugfix` мог arm QA без нового `bugfix_done` после latest `qa_fail` (stale leftover artifact / ignored `_append_event` False);
3. prepare/reducer тогда снова писал BUGFIX.

## Fix (shared + adapters)
- `loop/session_finalize.py`: `ownership_expected_step` / `apply_ownership_identity` — ownership по frozen `session_start_identity`.
- `harness/hooks/_lib.current_gate_identity` + Claude/Codex/DSH adapters — общая ownership overlay.
- `finish_bugfix`: fail-closed на persist `bugfix_done` и на `qa_failed` после finish; AC load_now предпочитает текущий bugfix артефакт.
- `rebuild_epic_projection`: доверяет armed QA/BUGFIX/AUDIT (demote только premature QA→BUGFIX).
