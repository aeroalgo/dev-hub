### In

- BACK, INTEG and relevant FRONT/shared mode instructions, lean gates, templates, and role-command skill copies.
- Codex/Claude source parity and generated runtime-entrypoint guidance.

### Out

- Capability registry vocabulary, executor behavior, evidence schema, and gate provenance already delivered by the capability/evidence epics.
- Browser execution through the capability executor, arbitrary shell execution, package installation, and product application code.

### Done when

1. A workflow author sees a hub-only branch or a managed `capability_checks` branch at every test decision point.
2. The active instruction corpus and runtime copies fail validation if a direct `pytest`, `cargo`, `npm`, or raw tests recipe can be read as the managed default.
3. Existing hub tests and FRONT parent-only boundaries remain explicit and valid.

### Forbidden after

Unqualified language-specific runner instructions, managed fallback to hub commands, hand-edited runtime copies that bypass the canonical source, and inventory tests that inspect only a small allowlist of files.
